# Issue #34 Phase 1: 複数 Waiting API 読み取り専用 PoC

正式機能の実装前に、実際の `translate.wordpress.org` の JSON 応答・ページングを確認するための手動検証です。この PR は **PoC の道具と手順だけ** を追加し、拡張機能には組み込みません。検索ボタン・全件走査・Warning 判定の正式実装は Phase 2 です。

## 安全上の制約

- 利用者が画面上の **「2ページ以内で取得開始」** を押すまで API を呼び出しません。
- `GET` のみ、同一オリジン、`filters[status]=waiting` のみ、ページは **1・2 の最大2件**。既存の翻訳者・ステータス設定は引き継ぎません。
- 通信は逐次実行で、ページ間は1秒待機。429 / 403 / 非 JSON / データ不整合 / ネットワークエラー時に即停止し、自動再試行はしません。
- 中止ボタンで実行中のリクエストを可能な限り中断し、次の GET を送信しません。
- 取得レコードは画面のメモリ内のみ。原文・訳文・翻訳者名は結果表示へ転載せず、項目の型・件数を表示します。保存、承認、却下、ローカルストレージへの書き込みは行いません。
- ブラウザーコンソールへの貼り付けは利用者の判断で行ってください。未知のスクリプトは実行しないでください。

## 手動実施手順

1. Chrome で `https://translate.wordpress.org/projects/wp-plugins/echo-knowledge-base/stable/ja/default/` など、**日本語の翻訳セット**を開きます（サインイン状態で取得可否も確認）。
2. 開発者ツールの **Console** を開き、このフォルダーの `multiple-waiting-poc.js` 全文を貼り付けて実行します。スクリプト自体の実行では API は呼び出されません。
3. ページ先頭の PoC 欄で **「2ページ以内で取得開始」** を押します。**Network** パネルの `Fetch/XHR` で `/api/projects/.../ja/default/` が最大2回、逐次に発生することを確認します。
4. 結果の HTTP ステータス・所要時間・各ページ件数・レコード項目の型・複数提案原文の件数を控えます。表示欄には原文・訳文やログイン名を出力しません。
5. 別の翻訳セットで実施する場合も、同じ最大2ページの上限を厳守します。繰り返し実行して 429 の閾値を探ることはしないでください。
6. 中止の動作確認は **必要な場合のみ** 行い、追加の負荷をかけないでください。中止後に次のリクエストが送られないことを Network で確認します。
